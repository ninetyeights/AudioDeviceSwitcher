# 应用路由回归检查

界面布局检查：`dotnet run --project tests/RoutingChecks -- --ui CKit tests/RoutingChecks/bin/ui`。
读取 12 个窗口的 XAML，加载统一主题并渲染预览图；去掉事件处理器，不执行窗口初始化中的音频、更新或设置写入操作。使用示例数据检查长名称、计划列表、应用音频行及表单布局。此检查不替代真实桌面上的下拉展开、键盘导航、不同 DPI 和屏幕尺寸的交互验收。

运行状态判定检查：

```powershell
dotnet run --project tests/RoutingChecks
```

同时验证真实 WASAPI 会话创建通知与订阅释放（需要可用的默认播放设备）：

```powershell
dotnet run --project tests/RoutingChecks -- --audio
```

后者只创建静音流，不更改系统默认设备、应用路由或音量。

手动回归：切换到有应用覆盖的配置，分别验证应用未启动、仅输出会话、仅输入会话、随后建立会话、手动修改路由、锁定修复、蓝牙设备断连重连。完全无会话应显示等待；任一方向有会话就应设置并验证输入、输出两条路由（例如 Chrome 播放视频但不开麦克风时，仍应验证输入路由）。读取失败应显示无法确认；只有成功读到不同设备时才告警。多进程应用需检查承载会话的 PID，不应被无会话的辅助进程影响。
